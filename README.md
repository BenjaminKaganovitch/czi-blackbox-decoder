# Black-box format decoding demo: Zeiss CZI

A first working demo of the "be your own crowd" method for proprietary
scientific file formats. Target: Zeiss CZI, a widely used microscopy format.

The rule for this demo: the official Zeiss library (`pylibCZIrw`) is used
only as a black box, to **write** sample files and to **read** them back as
an answer key. The parser was built only from byte differences between
controlled samples. No vendor code or documentation went into it.

## Pipeline

| Stage | Script | What it does |
|---|---|---|
| 1. Controlled samples | `gen_samples.py` | Writes files that each differ from a baseline in exactly one way (width, height, one pixel, pixel type, X/Y location, channel, Z). |
| 2. Byte diffing | `diff_samples.py` | Shows which bytes changed for each one-variable change. |
| 3. Independent parser | `our_parser.py` | Pure Python + numpy reader. Every constant is annotated with the experiment that revealed it. |
| 4. Answer key | `verify.py` | Generates random files (5 pixel types, 1 to 3 channels, 1 to 2 Z slices, 1 to 4 tiles per plane, random sizes, random and overlapping positions, 4 compression settings), reads them with both readers, and tie-breaks any disagreement against the pixels that were actually written. |

## What the diffs revealed

- File is a chain of segments, each with a 32-byte header: a 16-byte ASCII id
  (`ZISRAWFILE`, `ZISRAWSUBBLOCK`, `ZISRAWMETADATA`, `ZISRAWDIRECTORY`) plus
  two 64-bit sizes.
- Bytes that change in *every* diff are noise: two per-file GUIDs in the file
  header and a GUID inside each tile's XML metadata.
- The file header points to the directory; the directory lists one entry per
  tile; each entry holds pixel type, compression, file offset, and a list of
  20-byte dimension records (`X`, `Y`, `C`, `Z`, ...).
  `location_100_50` changed exactly two bytes per copy of that list (100 and 50);
  `channel_1` and `z_3` each flipped one.
- Pixels follow a fixed 256-byte tile header plus the tile's XML, stored
  row-major (`one_pixel`: row 3, column 5 landed at data offset 3 x 16 + 5).
- Pixel type codes: 0 Gray8, 1 Gray16, 2 Gray32Float, 3 Bgr24, 4 Bgr48.
- Compression code 5 payloads start with the standard zstd magic bytes;
  code 6 adds a short header whose first byte is its own length and whose flag
  turned on only when "HiLoByteUnpack" was requested (all low bytes, then all
  high bytes).
- Overlapping tiles: later tiles in file order are drawn on top.

## Results (500 random files per row, overlapping tiles allowed)

| Compression | Planes checked | Parser matches official reader |
|---|---|---|
| None | 1,523 | 1,523 (100%) |
| zstd | 1,523 | 1,523 (100%) |
| zstd + header | 1,523 | 1,523 (100%) |
| zstd + HiLo byte split | 1,523 | 1,182; all 341 mismatches resolved in our parser's favour |

## Unexpected finding: the answer key was wrong

All 341 mismatches were Bgr48 (16-bit colour) tiles saved with
`HiLoByteUnpack`. In every one, our parser returned exactly the pixels that
were written and the official reader did not. `repro_bgr48_hilo.py` shows it
in one file: of 900 values written, the official reader (pylibCZIrw 6.1.0)
returns only the first `width` correctly.

Before reporting upstream: retest on the newest release, and confirm against
the published CZI specification that this writer option is meant to be valid
for Bgr48.

Lesson for the method: the vendor reader is a strong answer key, not a
perfect one. Keeping the original written data as a tie-breaker is what
turned "our parser fails" into "we found a bug".

## Honest limits

- CZI has a vendor library and published spec, which is why it makes a good
  *first* target: every inference can later be checked. The method matters
  most for formats with neither.
- Only what this writer produces was tested. Real microscope files add
  pyramids, multiple scenes, JPEG-XR compression, attachments, and richer XML.
- No agent-driven decompilation was needed here; diffing plus recognising a
  known compression signature was enough. Harder formats will need it.

## Run it

```
pip install -r requirements.txt
python gen_samples.py
python diff_samples.py
python verify.py 500 --overlap --compression "zstd1:ExplicitLevel=3;PreProcess=HiLoByteUnpack"
python repro_bgr48_hilo.py
```
